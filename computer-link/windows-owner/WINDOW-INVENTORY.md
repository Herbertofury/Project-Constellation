# Explicit local window inventory draft

Private Windows-native read-only capability: separate Yes consent before enumerating visible top-level captions/PIDs/handles; local preview before any sharing. It excludes child-control text, screenshots, input, process access, admin, network, and application commands. Existing selected-snapshot grant and actual connected-client approval are still separate and required for transmission. Captions can contain private document/chat names, expressly warned before capture. No output is logged or persisted.

Bounded to32 rows,4096UTF8 bytes,256UTF16 title buffer and4096 enumerated windows; limit/truncation/invalidUTF16 refuses whole capture rather than quietly misrepresenting completeness. Control/bidi characters replaced for display. Empty captions are allowed observations, not a claim successfully read protected text. Window handles/PIDs/titles are unverified mutable observations, never future control authority.

Synthetic test creates only own temporary visible/hidden Win32 windows and filters to test PID; checks visibility, close disappearance and oversized-title refusal. Windows-target compile passed, no actual new Windows test yet. No full GUI-consent→inventory→paired-client acceptance yet, no inaccessible/secure desktop or all-browser UIA guarantee, no remote/dot connection. No failed file-dialog test retries.

Existing diagnostic workflow must not silently ship this new runtime before exact scope/privacy/security review. No installer/readiness claim. Official APIs: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows and https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowtextw .

Review correction: capture consent pins session generation after initial stop. Nested Disconnect/Exit/new grant invalidates late Yes before enumeration and before installing captured bytes. ## Keep/Discard refinement and proposed integrated acceptance
Captured bytes remain temporary during explicit local preview. Yes keeps the frozen bytes only if session generation is still current; No/close discards. This is not a share grant. Later Allow selected read and actual connected-client approval remain separate. File selection code and its failed test are untouched.

New actual GUI test authored: create synthetic visible marker window, deny capture, discard preview, keep preview, explicit read grant, real separate paired-client request, exact response byte count matching preview, Disconnect and Exit. It inspects the disposable CI desktop only in memory, does not log captions or payload, and uses numeric/count assertions; unrelated runner window captions can be part of this actual inventory (unlike own-PID unit test), never owner data. This is not exact-content digest proof, rendered pixels, tray-pointer QA or hostile process isolation. Windows compile check passed; actual execution pending review. Existing file-dialog failure is neither rerun nor declared fixed.

Acceptance refinement: inventory test now uses the test executable as the authenticated client process (distinct from actual owner process), calling the same paired_client API on a worker thread. It compares exact returned bytes to the locally previewed frozen snapshot entirely in memory; mismatch prints only a fixed message, not captions. Existing separate local-client.exe status scenarios remain unchanged. Thus this new test no longer claims to exercise the standalone CLI executable's read path. Discard selected-state and actual nested-Disconnect/late-Keep remain explicitly unverified GUI cases.
