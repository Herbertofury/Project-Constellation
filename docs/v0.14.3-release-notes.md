# Project Constellation v0.14.3 - Stable Live State Hotfix

v0.14.3 fixes the second-order live-state failures exposed by real ChatGPT use after v0.14.2: a completed chat could remain **Tool working**, and Execution Pulse could visibly flicker between active/healthy/warning colors while independent observers disagreed.

## Root causes fixed

- **Ordinary final-answer prose was still eligible as tool evidence.** ChatGPT can keep broad `aria-busy` / loading attributes on response-layout wrappers after the response is done. A completed paragraph containing words such as “verification”, “build”, “testing”, or “thinking” could therefore inherit a busy ancestor and look like a live tool row.
- **Too many writers were allowed to decide the primary state.** Live Sentinel, the legacy content-health loop, Output Vault health, and provider-network observations could briefly publish different answers and repaint the same HUD.
- **Provider traffic outlives the response.** Background ChatGPT POSTs and auxiliary requests can remain or restart after the assistant response is complete. Network traffic is useful telemetry, but it is not proof that the model is still generating.

## What changed

- **Semantic progress only.** Generic `aria-busy`, `data-loading`, and layout-loading wrappers are no longer independent generation evidence. Structured tool/progress surfaces, a real Stop/streaming control, a new user response boundary, assistant text growth, or a present-tense progress row are required.
- **Progress-line shape guard.** Weak ChatGPT tertiary/secondary rows must look like an actual progress line (for example `Searching…`, `Inspecting…`, `Searched…`) rather than merely containing a tool-like word somewhere in prose.
- **Current final controls are a completion boundary.** A Copy/feedback control on the current assistant answer suppresses leftover busy bits, while a fresh present-tense progress row or real Stop/streaming control can still keep the chat active. This does not reintroduce the v0.14.1 bug involving controls on an older answer.
- **Stable-state hysteresis.** Active evidence promotes immediately, but the running → completed transition requires a short quiet settle window. Transient DOM gaps cannot bounce the state on every mutation.
- **One canonical primary state.** Popup Chat Pulse, completion notifications, content status, and Execution Pulse consume the versioned Live Sentinel state. Legacy content pushes are rejected by the background live-tab map.
- **HUD race guard.** The Sentinel guards the Execution Pulse host/shadow state and repairs a stale writer in a microtask before the next paint. Constellation-owned DOM mutations are excluded from Sentinel observation, preventing a self-triggering repaint loop.
- **Network demoted to telemetry.** Pending/stream-likely provider requests no longer promote a completed tab back to Active. They remain visible in the activity timeline and network metric.
- **Output Vault stays secondary.** Saved/page mismatch warnings no longer put completed chats into the fast active-health polling lane or decide the main chat color/status.
- **Hot upgrade is version-aware.** Existing tabs running an older Sentinel are reinjected with v0.14.3 instead of being accepted just because a Sentinel object already exists.

## Regression and stability testing

The browser regression now covers both real failures reported from ChatGPT:

1. An older completed answer has Copy controls while a newer response shows `Searched 20 websites`, `Searching the web`, `Inspecting mob animation rendering logic`, and generic tool rows. The chat must remain Active until the current progress settles.
2. A completed current answer contains prose such as `The production release pipeline also passed verification, build, packaging, release publishing, and artifact upload`, while stale layout wrappers remain `aria-busy` / `data-state=loading`. The chat must remain Completed.

Additional stress coverage repeatedly writes incorrect active/warning/danger HUD states while the completed chat is sampled on animation frames; **zero bad frames** are allowed. A full content/health integration fixture also alternates pending provider traffic, keeps an Output Vault mismatch active, churns stale busy attributes, and verifies the primary HUD stays `healthy / Chat complete`. Genuine `Searching the web` progress must still switch immediately to Active and return to Completed after the settle window.

## Browser acceptance note

The automated suite runs the unpacked extension logic in Chromium. This execution environment also includes a system Linux Chromium and was explicitly tested as a custom-browser target. However, the sandbox applies an administrator navigation policy to spawned Chromium (`ERR_BLOCKED_BY_ADMINISTRATOR`) and has no authenticated user browser session available, so an actual signed-in `chatgpt.com` acceptance run cannot be truthfully performed here. The release therefore treats signed-in live-site use as the final user acceptance step rather than claiming it passed in an inaccessible session.
