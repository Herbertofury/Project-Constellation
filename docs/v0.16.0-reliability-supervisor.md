# v0.16.0 Browser-wide Reliability Supervisor

This layer is additive to the v0.16 AI Command Center, Chat Vault, closed-chat watch, notification repair, organizer QoL, and Living Project Rooms work. It does not replace those systems.

## All open ChatGPT tabs

Project Constellation now supervises every already-open ChatGPT conversation independently. The lightweight tab supervisor remains active when a page is hidden, while a Manifest V3 background alarm enumerates all open ChatGPT tabs once per minute, wakes their supervisor, and hot-injects it after an extension startup/update when necessary. Recovery state is per chat rather than tied to the focused browser tab.

## Stale, dead, and interrupted chat rescue

When Refresh Recovery is enabled, an unfinished existing ChatGPT conversation can be automatically rescued after:

- an explicit message-delivery timeout, connection interruption, response interruption, or send failure;
- a corroborated dead/stalled state that exceeds the dead-recovery threshold; or
- two hours without meaningful progress on an unresolved user/running turn.

Completed idle chats do not qualify. Auth-required, unavailable, rate-limited, and approval-blocked states are not blindly reloaded. Per-chat cooldown and attempt caps prevent recovery loops.

Before reload, currently visible chat state is checkpointed. After the same tab reloads and the native composer hydrates, Constellation submits a continuation prompt that preserves the exact objective, decisions, project/repository/file/Drive/GitHub identities, paths, hashes, run/job IDs, verified tests, blockers, no-repeat history, and exact unfinished next action. The prompt treats the final attempted write/tool side effect as potentially partial and requires verification before repetition.

A non-empty composer is never overwritten.

## Permission autopilot across tabs

The browser-wide approval supervisor enumerates all open ChatGPT tabs and fans approval scans out concurrently. Actual permission execution stays single-owner: it delegates to the established `PC_APPROVAL_RECOVERY_SCAN` in-page handler, preserving configured Always Allow / allow-once behavior instead of introducing a second competing click implementation.

## Capacity warning

The reliability lane promotes the existing Live Sentinel's authoritative `capacity-watch`, `capacity-handoff`, and `capacity-reached` states, including tool/structured-message pressure, before falling back to local turn/character thresholds. That allows tool-heavy chats to warn before visible-text counters alone would detect the risk.

## Project discovery

ChatGPT `/g/g-p-*` routes and visible project sidebar entries are mirrored as first-class provider project identities from every supervised ChatGPT tab, so project tracking is no longer dependent on which tab happens to be foregrounded.

## Verification

- `tests/tab-supervisor-core.test.mjs` for failure classification, two-hour rescue, completed-chat exclusion, cooldowns, authoritative capacity states, and continuation-prompt invariants;
- `tests/reliability-supervisor-contract.test.mjs` for all-tab enumeration, hidden-tab supervision, hot bootstrap, bounded reload, single-owner approval execution, project discovery, continuation send, and packaging without loss of Command Center files;
- `tests/smoke/multitab_reliability_smoke.py`, which loads the packaged extension in extension-capable Chromium, keeps one ChatGPT tab in the background, and requires both stale unfinished chats to reload and actually submit the continuation prompt.
