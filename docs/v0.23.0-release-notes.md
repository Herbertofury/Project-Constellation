# Project Constellation 0.23.0

Project Constellation 0.23.0 repairs silent alert failures, strengthens the Rust
browser hub under bursts and stalled connections, improves the attention inbox,
and makes Windows repair and rollback more dependable. It preserves the full
original application and Computer Tools migration from 0.22.0.

## Download and install

Use **Constellation-0.23.0-Windows-Setup.exe** for the compact Rust hub, browser
sensors and native Computer Tools. Run **Install / Repair** to install or update.
The installer is self-contained and per-user; no Rust toolchain or destination
payload download is required. Keep the release checksum file with the EXE.

Use **Project-Constellation-v0.23.0-Windows-Desktop-Setup.exe** or
**Project-Constellation-v0.23.0-Windows-Portable.zip** for the full desktop shell,
files, terminal, saved tasks and chat bridge. The full Chromium extension,
Firefox sensor and Linux browser hub remain separate downloadable assets.

Enable the sensor in each browser/profile you want to monitor. Setup opens the
right extension page and copies its prepared folder path. In Agent Monitor,
choose **Connect browser hub**, give the profile a useful name, and use
**Test alert**. The unsigned Firefox sensor remains temporary and needs
reloading after Firefox restarts. Existing extension identity and local data
are preserved; do not uninstall a working extension before securing its data.

## Alerts that recover from delivery failures

- A failed sound or desktop-notification channel retries independently after
  2, 10 and 30 seconds. A channel that already succeeded is not replayed by
  those retries. The retry budget and successful-channel state survive service
  worker restarts. Exhausted failures remain visible in delivery diagnostics.
- Acknowledgement, snooze, mute, source availability and shared alert ownership
  remain authoritative. A storage failure while claiming delivery does not
  silently consume an alert that was never sent.
- Sensors require a successful acknowledgement that an observation was stored.
  Transient failures retry after 250 ms, 1 second and 3 seconds, then stop.
  Explicit refresh remains available. Old asynchronous failures and page
  shutdown cannot schedule a retry for the wrong document.
- Loading earlier conversation history or mounting hidden hydration nodes no
  longer creates a false new run and duplicate incident. A delayed observation
  from an earlier document cannot displace the current tab's evidence.
- A repeated native observation advances its ordering timestamp even when its
  visible state is unchanged. An older delayed recovery message therefore
  cannot clear a newer active problem.

## A more resilient shared browser hub

The Rust hub combines redundant pending snapshots into the latest complete
state while preserving direct responses and focus commands in order. This
prevents ordinary bursts of chat observations from filling the old small mixed
queue and dropping a healthy browser connection. Real transport coverage now
includes a 96-tab burst with a paused second reader, retained incidents and a
subsequent acknowledgement.

A native request that stops answering closes the stale port and enters the
existing bounded reconnect path. Failed imports into local storage remain
retryable; an imported-state signature is only accepted after persistence
succeeds. Existing on-demand startup, independent browser/profile leases and
five-second final-disconnect grace are preserved. There is no idle polling loop.

## Clearer attention triage and live-state evidence

Search and browser selection apply to the inbox and the chat list. The inbox
adds **Needs you**, **Acknowledged**, **Snoozed** and **Source unavailable** views.
Resolved history remains available. Local and hub history are matched one to
one so differing observation timestamps do not duplicate the same episode and
an unmatched repeated failure is not discarded.

Disconnected chats and incidents remain visible as unavailable. Failed,
incomplete or timed-out status reads retain last known information, disable
stale actions and stop claiming connected coverage. Fresh valid evidence
restores the controls. An empty filtered view reports its actual result count.

All matching rows remain rendered. Indexed lookup and incremental DOM updates
reuse unchanged rows, and keyboard focus survives unrelated changes and row
reordering. No chat/incident cap, pagination or viewport suppression is used.

In an isolated Chromium test with 2,000 synthetic chats and 1,000 incidents,
median unchanged-state refresh fell from 315.7 ms to 15.8 ms; a two-row update
fell from 387.6 ms to 21.0 ms. Full cold rendering remained comparable
(301.2 ms versus 298.9 ms). These are 11 interleaved full-layout samples for
this fixture, not a guarantee for every PC or signed-in provider. The complete
source identities, tails, smaller workloads and heap measurements are in
`docs/AGENT-MONITOR-PERFORMANCE-0.23.0.json`.


## Windows recovery fixes

- Verification checks a retained newer setup manager after rolling the active
  application payload back. A missing or corrupt manager is unhealthy.
- Same-payload Repair can replace that damaged retained manager with a verified
  copy, preserving the changed original.
- If a failed upgrade encounters later edits in the newly activated browser
  folder, recovery preserves that directory in a named recovery folder and
  restores the previous browser directory. The preservation path remains in
  the result even if a later registry restoration also fails.
- A pending recovery journal makes Verify unhealthy until recovery completes.

The actual Windows acceptance harness deliberately corrupts the retained setup
manager after rollback, detects the damage, repairs it and checks preservation.
Release assembly requires that check plus install, repair, diagnostics, rollback,
uninstall, setup/owner UI and restored integrations. Cross-compilation alone
cannot satisfy those nine checks.

## Current desktop and build stack

The desktop upgrades to **Electron 45.5.0** and **electron-builder 26.18.1**.
Current release jobs use **Node 26.13.1**, **Rust 1.100.1** and **Playwright 1.65.2**.
Native dependencies advance to **url 2.5.9** and **sha2 0.11.2**. The digest-format migration retains the same lowercase 64-character SHA-256 bytes, verified against the prior implementation and standard/binary vectors.

The native monitor reports product version **0.23.0**, while its compatible wire
protocol remains version 1. Official-source version evidence and any causally
repaired dependency changes are recorded in `docs/RELEASE-STACK-0.23.0.json`.

## Verification and remaining boundaries

The matching release receipt identifies the exact source commit/tree, production
extension configuration, Windows setup/runtime acceptance and artifact hashes.
All five required workflow families must pass before publication. The release
workflow downloads the published assets and verifies their hashes again, then
synchronizes and reads back the live Wiki. Source, tests, original features,
licenses, historical releases and private recovery records remain preserved.

Local Chromium DOM fixtures and native transport/transaction tests are distinct
from installed-extension and real Windows execution. The local restricted
renderer cannot provide installed MV3 service workers; those tests remain
mandatory on the hosted release runner. Physical speaker output, actual OS
notification visibility, the owner's browser enrollment and signed-in backup
round trips remain target-machine acceptance. Executables remain unsigned and
Firefox distribution remains temporary, so this release stays a **prerelease**.

Historical Computer-Link Git bundles stay in the private recovery checkpoint;
this release neither publishes them nor deletes the original repository.
