# Project Constellation v0.13.0 — Execution Pulse + Tool Watchdog

Project Constellation is a performance-first Chromium MV3 continuity workspace for AI chats, projects, recommendations, links, code, files, artifacts, recovery, and provider connections. v0.13.0 turns the bottom-right Live Chat Health surface into **Execution Pulse + Tool Watchdog**: a compact local proof monitor that tells you whether the model/tool pipeline is actually moving, quiet-but-alive, stuck on a tool/request, or apparently dead. It preserves the v0.12 Capacity Guard + Safe Handoff foundation and adds no provider-page network requests.

## Execution Pulse + Tool Watchdog — know if the chat is alive

The configurable bottom-right HUD now presents an explicit execution pulse instead of a vague spinner. It combines only locally observable evidence: conversation DOM progress, the recent tool-event timeline, passive MV3 request lifecycle, page/catalog freshness, Project Integrity, Capacity Guard, and recovery state.

The HUD exposes **Last proof**, **Network**, **Activity**, **Tool pulse**, **Project**, **Page**, **Capacity**, and **Handoff**. Its collapsed form still retains the current activity phase and proof age, so it remains useful without covering the chat.

Tool-heavy conversations get a dedicated watchdog:

- **Tool working** — a current tool step has fresh tool-card/DOM or provider-network proof.
- **Tool quiet** — the tool is still present but has gone quiet long enough to watch closely.
- **Tool call looks stuck** — the tool remains on-screen/busy but no tool, conversation, or request-stream progress crossed the hard threshold.
- **Tool call appears dead** — the same no-progress condition crossed the separate dead threshold.
- **Request looks stuck** — a provider request is technically open, but the response/tool/DOM proof stopped moving.
- **Chat appears dead** — active work has produced no observable proof past the dead threshold. This is deliberately labeled as a local signal, not a claim that the provider backend definitively terminated.

Repeated generic provider rows such as **Called tool** are counted as distinct progress events by timeline fingerprint and step count. A repeated label therefore does not look frozen when new tool events are still arriving. Conversely, one zombie pending request cannot keep the HUD green forever.

Constellation does not press Retry to manufacture recovery. Delivery/connection interruptions remain browser-refresh-only, while Tool Watchdog is diagnostic and exposes the exact state instead of hiding it.

The same fresh live-health state is projected into Home, Attention, Inspector, Recovery, Search, and Organizer cards, so you can see a stuck/dead tool conversation even when you are not staring at that tab.

## Knowledge Vault — never lose the useful part of a chat again

Captured conversations are no longer just transcript blobs. Constellation deterministically extracts durable, attributable knowledge into a local graph:

- recommendations and suggested tools/mods/packages;
- every useful URL plus provider/domain classification;
- GitHub/GitLab repositories with owner/repo identity;
- CurseForge, Modrinth, Nexus Mods, MCPEDL, Planet Minecraft, Minecraft Marketplace, and other mod resources;
- packages, media, documents, cloud links, and external references;
- generated/downloaded files and their exact originating chat;
- decisions, ideas, TODOs, follow-ups, and unresolved next actions;
- code blocks, language, detected symbols, paths/filenames, commands, and versions;
- project continuity pointers such as the latest recommendation, decision, artifact, version, code reference, follow-up, and exact chat where work last happened.

Every item preserves source provider, exact chat URL, source turn, project/workspace relationship, related URLs, file references, versions, and content fingerprints. Search can therefore answer queries like `minecraft`, `ModernFix`, `Forge crash`, a GitHub owner/repo, a filename, a version, or code symbol and return both the useful item and **where it came from**.

Extraction is local and deterministic. It does not call OpenAI or another model just to organize a chat.

## Thousand-chat scaling

The Knowledge Vault is built for a lifetime archive rather than a few hundred rows:

- changed turns are fingerprinted so unchanged content is never re-extracted;
- knowledge items use deterministic canonical keys/content hashes for deduplication;
- new/changed content is processed in tiny bounded batches while the browser is active;
- large historical backfill accelerates only when Chrome reports the machine idle;
- IndexedDB indexes drive counts/search/project relationships instead of rescanning full transcript text;
- universal search indexes knowledge records independently from raw turns;
- project-continuity summaries are incrementally maintained instead of reconstructed on every Home render;
- all extraction runs outside the AI page render/input path and generates zero provider requests.

The existing adaptive request governor remains in force for the separate provider-fetch lane: same-provider single-flight, freshness skips, conditional requests, 429/503 `Retry-After`, exponential backoff, jitter, and shared cooldowns.

## Live Chat Health foundation

Supported AI pages now get a configurable Shadow-DOM HUD (bottom-right by default) that answers the question the provider UI often cannot: **is this chat really still working?**

Execution Pulse keeps the Live Chat Health foundation and combines local DOM progress, tool/activity evidence, catalog state, Project Integrity, and passive MV3 network telemetry. In addition to the dedicated Tool Watchdog states above, it distinguishes:

- **Working / Thinking** — real model/request or visible semantic progress exists;
- **Quiet working** — little UI motion but recent semantic/network evidence indicates progress;
- **Stalled** — no meaningful DOM/tool/network progress beyond the configured threshold;
- **Blocked approval** / authentication required;
- **Refresh required** for delivery/connection failure;
- **Rate limited** / provider cooldown;
- **Paused** / resume available;
- **This tab is behind** when an authoritative newer captured revision exists;
- **Degraded render** when meaningful recent message text exists in the DOM but is hidden/disappeared;
- **Old project version**, **project rollback**, **artifact/project conflict**, and **regression risk** from Project Integrity;
- follow-up/unfinished-work signals;
- healthy/idle state when nothing needs intervention.

A long tool call does **not** become “stalled” merely because visible text has not changed. Passive `chrome.webRequest` telemetry tracks request start/response/completion/error state without intercepting or modifying requests, while the watchdog also ages the oldest pending request and latest real progress so a zombie request cannot remain active forever. No request bodies or extra headers are collected.

### Stale-tab and degraded-page protection

“This tab is behind” is intentionally conservative. It requires authoritative full-export/full-DOM coverage or catalog evidence newer than the current route plus a hydrated, non-running page. A partial/metadata snapshot cannot falsely force a refresh.

Render-degradation checks are also bounded to recent visible turns and look for cases such as `visibility:hidden`, near-zero opacity, or `innerText` disappearing while meaningful `textContent` remains.

## Conversation Capacity Guard + Safe Handoff

Live Chat Health now watches conversation size as a separate safety signal. Provider context/conversation ceilings vary by model and are not exposed as a stable exact number, so Constellation deliberately uses **configurable proactive safety thresholds** instead of pretending it knows the provider's remaining token budget.

- Early warning defaults to 180 captured turns or 240k captured characters in the current mounted session.
- Secure-handoff defaults to 260 captured turns or 400k captured characters.
- An explicit provider message such as a maximum-conversation/context-length warning immediately promotes the guard to critical.
- IndexedDB turn counts are read through an index count, not a transcript scan; current-session character volume is maintained incrementally as turns change.
- Capacity warnings remain visible even while tool/network work is active, so a long-running answer cannot silently carry the chat into a dangerous handoff boundary.
- **Secure handoff** creates a durable checkpoint containing exact source chat/project/version lineage, bounded recent turn context, extracted durable knowledge, files/resources, and capacity evidence, then copies a continuation-ready Markdown handoff to the clipboard.
- If Google Drive is already connected and provisioned inside Constellation, the explicit handoff click requests a full snapshot with round-trip verification before reporting Drive verified. If Drive cannot verify on that click, the local checkpoint remains intact and Drive stays marked pending rather than faking success.

The handoff is intentionally a compact continuation index. It never replaces or deletes the full local/Drive catalog.

## Recovery rules remain strict

- **Message delivery timed out / connection interrupted / connection lost** => browser reload only. Provider `Retry` is never clicked.
- **Too many requests / 429** => shared provider cooldown. Hidden recovery closes and does not advance into the next chat until cooldown expires.
- Approval/stale recovery => exactly one minimized reusable recovery window/tab after explicit Approval Autopilot enablement.
- Manual Full Capture => exactly one visible reusable capture window/tab.
- Normal catalog => zero crawler tabs.

## Project Integrity

Project Integrity remains local/deterministic and now feeds the Live Health HUD. It detects active chats on old versions, project rollback, conflicting same-version artifacts, feature regression signals, unanswered/follow-up work, blocked/refresh/rate-limit states, and other project damage without spending model/API requests.

## Performance contract

The original optimization engine remains first class:

- AI-page content scripts perform **zero provider network requests**;
- no message trimming, deletion, hiding, second virtualization, or `content-visibility` shortcuts;
- capture/index/sync work is incremental and asynchronous;
- the HUD itself is a tiny Shadow-DOM surface with adaptive polling and no framework runtime;
- hidden historical extraction is idle-aware;
- remote Drive/GitHub work remains isolated from provider content contexts.
