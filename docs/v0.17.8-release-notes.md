# Project Constellation v0.17.8 — Scheduled Task Command Center

Project Constellation v0.17.8 turns the v0.17.7 Scheduled Task Guardian into a premium task-health command center. The existing Guardian still protects access to ChatGPT Scheduled with one bounded offscreen workspace when framing is allowed and heartbeat fallback when it is not, but it can now surface real task state changes as native desktop notifications.

## Premium alert layer

- **Run completed** — fires only when Guardian observes a new successful run identity or run timestamp.
- **Run failed** — warns when a new observed run ends in a failure/error/cancel/timeout-style state.
- **Run completed · task is paused** — combines simultaneous run completion + pause into one actionable alert instead of two popups.
- **Run failed · task is paused** — combines failure + pause with high-salience attention behavior.
- **Task paused / needs attention** — covers explicit pause, disabled/suspended state, approval/action required, blocked/auth/permission state, and other bounded attention flags exposed by the signed-in Scheduled experience.
- **Task resumed** — confirms when an observed paused task becomes active again.

Native Guardian notifications include **Open Scheduled** and **Mute 1 hour** actions. Important attention alerts request persistent notification visibility; ordinary successful-run/resumed notices remain lower-salience. A test-popup button verifies the local notification path without changing a scheduled task.

## Command-center UX

Home and the side panel now expose:

- task-state observation toggle;
- desktop popup toggle;
- successful-run alert toggle;
- smart state-change alert toggle;
- existing keep-warm, auto-repair, cadence, Repair now, and Open Scheduled controls;
- observed / active / paused / needs-attention counters;
- recent deduplicated Guardian activity;
- popup mute state and latest observed task-state time.

The toolbar badge can also surface an `S#` attention count when scheduled-task attention is the highest-priority Constellation badge state.

## Truth and privacy boundary

Guardian does **not** use a timer to claim that a run completed. The first task snapshot becomes a baseline; completion/failure/resume alerts require a later observed state transition. If real task state is unavailable, the UI says so instead of manufacturing activity.

The observer retains bounded task-health metadata only: task ID, short title, status/enabled state, next/last run timestamps, run ID/status, recurring flag, attention flag/reason, conversation ID, source, and observation time. Traversal explicitly skips prompt, instructions, message, content, result, output, body, and text payload branches. Guardian does not persist task prompts, run results, or Scheduled page HTML.

Task endpoint discovery uses passive Resource Timing metadata and bounded same-origin authenticated reads. It does not monkeypatch `window.fetch`, intercept provider request bodies, or modify ChatGPT requests.

## Safety / performance invariants

- Canonical Scheduled route: `https://chatgpt.com/scheduled`; legacy `/schedules` and `/tasks` inputs are clamped to the canonical route.
- No inactive or minimized ChatGPT tabs/windows are created.
- Existing ChatGPT tabs are never navigated/hijacked by Guardian.
- Open Scheduled is explicit foreground user navigation only.
- No new Chrome permission is added for v0.17.8; the notifications permission already existed in v0.17.7.
- Offscreen code still contains no polling fetch loop; supervision remains bounded by the existing MV3 alarm cadence.
- Scheduled tasks remain ChatGPT cloud jobs; the Guardian browser surface is management/health protection, not the scheduler itself.
