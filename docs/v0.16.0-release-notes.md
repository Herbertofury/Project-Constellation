# Project Constellation v0.16.0 — Living Project Rooms + AI Command Center + Reliability Supervisor

v0.16.0 is a functional reliability and workflow release, not a cosmetic tier rename. It combines the Living Project Rooms project-router work, the AI Command Center / Chat Vault / closed-chat QoL work, and the browser-wide Reliability Supervisor into one Project Constellation line.

## AI Command Center and QoL

- Chat Vault and organizer surfaces make captured chats easier to browse, group, recover, and act on.
- Command Center actions turn attention items into working controls rather than dead status cards.
- Closed-chat watch and vault bridging keep stale/closed work visible and recoverable instead of silently disappearing.
- Notification repair and attention QoL improve reliable delivery and triage of chat state.
- Existing Output Vault, Execution Pulse, Tab Beacons, Knowledge Vault, Drive/GitHub persistence, and project continuity remain intact.

## Living Project Rooms

- Project-aware routing and room state give project tabs durable, explicit workspace identity instead of loose browser-title grouping.
- Project routing is verified separately and then reconciled into the final v0.16 accepted tree so Command Center and reliability features do not erase project-room behavior.

## Browser-wide Reliability Supervisor

- **Every already-open ChatGPT tab is supervised independently**, including hidden/background tabs. Reliability no longer depends on whichever tab is focused.
- A service-worker heartbeat enumerates all open ChatGPT tabs once per minute, wakes their per-tab supervisor, and can hot-bootstrap the reliability agent after extension startup/update.
- When Refresh Recovery is enabled, explicit delivery timeout, connection interruption, response interruption, send failure, corroborated dead/stalled state, or an unfinished two-hour stale turn can trigger bounded recovery.
- Recovery checkpoints visible chat state, reloads the same existing tab, waits for the native composer, and submits a continuation prompt that preserves objective, decisions, project/repository/file/Drive/GitHub identities, paths, hashes, run/job IDs, verified tests, blockers, no-repeat history, and the exact unfinished next action.
- The continuation prompt treats the final attempted tool/write side effect as potentially partial and requires verification before repeating it.
- Completed idle chats are excluded. Auth/rate-limit/unavailable/approval-blocked states are not blindly reloaded. Per-chat cooldown and attempt caps prevent loops. A non-empty composer is never overwritten.

## Permission recovery on multiple tabs

Approval Autopilot now fans the existing tested permission-recovery handler across all open ChatGPT tabs concurrently. It preserves configured Always Allow / allow-once behavior without adding a second competing click implementation.

## Better project tracking

ChatGPT `/g/g-p-*` project routes and visible project-sidebar entries are mirrored as first-class provider project identities from every supervised tab, so discovering a new project no longer depends on the active tab.

## Earlier capacity warning

The reliability lane promotes the existing authoritative `capacity-watch`, `capacity-handoff`, and `capacity-reached` Live Sentinel states, including structured/tool-message pressure, before falling back to local turn/character thresholds. Tool-heavy chats therefore receive the stronger existing runway signal instead of relying only on visible text size.

## Verification

The final v0.16 release must pass the combined project-router, Command Center/QoL, reliability, validation, scale, and browser acceptance gates. Reliability-specific proof includes:

- unit coverage for provider-failure classification, two-hour rescue, completed-chat exclusion, cooldowns, authoritative capacity states, and continuation invariants;
- static integration coverage proving Command Center/Chat Vault files remain packaged alongside the supervisor;
- a real Chromium extension-runtime round trip through the stable extension ID;
- a two-tab Chromium smoke where one ChatGPT tab is backgrounded and **both** stale unfinished tabs must reload and actually submit the continuation prompt.

Release publication is complete only when the accepted source, production build, checksums, GitHub release/tag, and canonical Google Drive artifacts all agree on the same v0.16.0 lineage.
