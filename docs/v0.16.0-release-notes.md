# Project Constellation v0.16.0 — Reliability Supervisor

v0.16.0 changes Project Constellation from a foreground-tab assistant into a browser-wide ChatGPT reliability supervisor.

## What changed

- **All open ChatGPT tabs are supervised independently.** The extension no longer relies on the foreground capture loop to notice failures. A service-worker heartbeat enumerates every open ChatGPT tab once per minute and wakes the per-tab supervisor.
- **Hidden tabs stay observable.** The reliability path does not return early when `document.hidden` is true. Hidden tabs keep lightweight state, project, failure, approval, and continuation monitoring.
- **2-hour stale-chat rescue.** When Refresh Recovery is enabled, an unfinished ChatGPT turn that has made no progress for two hours is eligible for automatic rescue. A genuinely completed idle chat is not continued.
- **Dead/interrupted chat recovery.** Message-delivery timeout, connection interruption, response interruption, send failure, stale-page, and corroborated dead/stalled states can trigger bounded recovery instead of sitting indefinitely in Needs Attention.
- **Reload + continue.** Before recovery, the current visible chat state is ingested into Project Constellation. The tab is reloaded and, after ChatGPT hydrates, Constellation inserts and sends a continuation prompt that tells the next turn to preserve identities, checkpoints, completed work, blockers, tests, and the exact unfinished next action while verifying possibly-partial side effects before repeating them.
- **Loop protection.** Recovery respects the existing Refresh Recovery enable switch, cooldown, per-chat recovery cap, and does not reload auth/rate-limit/approval-blocked states.
- **Permission autopilot per tab.** Every ChatGPT tab independently observes Drive/GitHub/connector permission surfaces and can use the configured persistent `Always allow` preference rather than waiting for a serial foreground sweep.
- **Project discovery from real ChatGPT project routes and sidebars.** `/g/g-p-...` routes become first-class provider project identities, and visible project sidebar entries are continuously mirrored into the Constellation project catalog.
- **Capacity alerts are visible and browser-notified.** Proactive warning and handoff boundaries are surfaced before provider hard-stop text where local evidence reaches the configured limits.
- **Extension-update bootstrap.** Existing open ChatGPT tabs can be injected with the new supervisor after extension update/startup instead of requiring the user to visit every tab manually.

## Recovery safety

Automatic recovery is intentionally bounded. It will not overwrite a non-empty composer, will not auto-reload a chat blocked on an approval/auth/rate-limit state, and uses a cooldown plus per-chat recovery cap. The continuation prompt treats the final attempted tool/write action as potentially partially completed and requires verification before repeating it.

## Verification added

- `tests/tab-supervisor-core.test.mjs` covers explicit provider failures, 2-hour stale-running rescue, unanswered-user rescue, completed-idle exclusion, approval exclusion, cooldown behavior, capacity boundaries, and continuation-prompt invariants.
- `tests/reliability-supervisor-contract.test.mjs` enforces all-tab enumeration, hidden-tab wakeups, service-worker heartbeat, reload recovery, existing-tab bootstrap, project discovery, per-tab approval handling, continuation send, and packaging of the supervisor files.

This release is intentionally focused on reliability behavior rather than cosmetic labels or premium-themed UI changes.
