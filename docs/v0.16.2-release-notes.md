# Project Constellation v0.16.2 — Hidden-Tab Rich File Capture

v0.16.2 closes a remaining gap in the v0.16 reliability supervisor: background ChatGPT tabs already preserve chat, turn, status, project, approval, and recovery state, but the legacy rich-capture queue intentionally shuts down when `document.hidden`, so file and attachment links mounted while a tab stays in the background could be missed until the tab was revisited.

## Fixed

- **Background attachments are captured while the tab stays hidden.** The per-tab supervisor now owns a narrow hidden-file lane for file, attachment, download, sandbox, Google Drive/Docs, GitHub, Dropbox, OneDrive, and common document/archive/image links.
- **No heavy foreground capture duplication.** The hidden-file lane is disabled while the tab is visible; the existing foreground rich-capture implementation remains the owner there.
- **Mutation-driven without mutation spam.** File-relevant hidden DOM changes mark the lane dirty and are coalesced. File-only `href`, `data-testid`, and `aria-label` mutations do not create extra foreground supervisor evaluations.
- **Service-worker safety scan.** The existing once-per-minute all-tab supervisor wake forces a hidden-file safety scan, so timer throttling or a missed mutation cannot leave a background attachment invisible indefinitely.
- **Canonical brain ingestion.** Hidden file records use the same `brain.fileKey`, provider URL classification, `FILE_UPSERT`, and `PC_BRAIN_INGEST_BATCH` path as the rest of Constellation.
- **Failed writes remain retryable.** The hidden-file seen cache advances only after the canonical brain acknowledges a successful ingest. A failed/ignored write is not silently treated as captured.
- **Bounded resource use.** Scans are limited to file-relevant selectors, throttled, batch-limited, and capped; cached fingerprints are bounded as well.

## Verification

- Adds `tests/hidden-file-supervisor-contract.test.mjs` for hidden-only ownership, throttling, canonical ingestion, forced safety-scan behavior, foreground-performance isolation, observer coverage, and retry-safe seen-state behavior.
- Adds `tests/smoke/hidden_file_capture_smoke.py` with a split Chromium proof required by Playwright/Chrome automation semantics: a protocol-native hidden renderer must persist hidden attachment mutations with `hidden-tab-supervisor` provenance, while a separate genuine inactive UI-strip ChatGPT tab must remain discoverable through `chrome.tabs` and accept the real `PC_TAB_SUPERVISOR_TICK` message.
- The hidden-renderer smoke also covers an existing link becoming downloadable only through a later `download=` mutation.
- Existing multi-tab rescue, project discovery, approval, Drive auto-sync, extension-load, and full-capture smokes remain part of the full Verify gate.

The split browser proof is deliberate: Chromium's `Target.createTarget(hidden:true)` guarantees a hidden renderer but, by protocol contract, is not present in the tab UI strip and cannot be `forTab:true`; Playwright-controlled UI-strip tabs remain renderer-visible under automation even when Chrome reports them inactive and their native window is minimized. The unit contract bridges those two browser proofs by requiring `PC_TAB_SUPERVISOR_TICK` to force the hidden-file safety scan whenever `document.hidden` is true.

This point release preserves the v0.16.1 Drive auto-sync connection guard and the full v0.16 multi-tab rescue behavior.
