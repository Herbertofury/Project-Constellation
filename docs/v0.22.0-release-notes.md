# Project Constellation 0.22.0

This release brings Windows setup, browser-bound native monitoring and the
Computer-Link native tools into Project Constellation. It retains the verified
0.20.1 application and the 0.21.0 attention, alerting and cross-browser work.

## Install

Use **Constellation-0.22.0-Windows-Setup.exe** for the Rust monitor and native
Computer Tools. Setup installs per user, prepares the browser sensor folders,
registers native messaging and offers Repair, diagnostics, rollback and uninstall.
No Rust toolchain or payload download is needed on the destination PC.

Enable the sensor in each browser/profile. Chrome, Edge and Opera GX use their
extension page's Developer mode and Load unpacked controls. Firefox currently
uses an unsigned temporary sensor that must be reloaded after restart. Setup
opens the relevant page and copies the correct path. In Agent Monitor, choose
**Connect browser hub**, then use **Test alert** to verify the output device.

The separate **Project-Constellation-v0.22.0-Windows-Portable.zip** and desktop
installer provide the full desktop shell, files, terminal, saved tasks and chat
bridge. The compact native installer and the full desktop distribution have
distinct filenames and receipts. Consult the attached checksums before install.

## Browser and alert reliability

- The hub starts on demand and exits five seconds after the final browser
  connection closes. Opening a normal browser window reconnects automatically.
- Closing all normal windows releases the native connection even when Chrome
  remains running in background mode. Multiple browsers and profiles retain
  independent leases; closing one does not stop the others.
- Concurrent starts elect one broker. A delayed reader from an old connection
  cannot disconnect or mutate the replacement connection.
- Shared mute, volume, alert channels and incident acknowledgements survive
  output-browser changes and native restarts. Offline sources stay explicitly
  unavailable until fresh observations arrive.
- The dashboard reports paused and connecting states, permits cancelling a
  pending hub connection, and never treats an opaque acknowledgement as proof
  that the hub is connected.
- Recovery rechecks the conversation, current holds and exact draft after
  waiting for Send. User edits, navigation, a replaced composer, new permission
  or review prompts, and a provider that resumes or finishes cancel the send
  without forcing a reload or switching the active tab.

## Computer Tools migration

Native local inventory, snapshots, folder selection, new-file export, HTTPS
handoff, window focus, stdio MCP, workspace operations and owned worker
supervision are integrated. The native application is named **Constellation
Computer Tools**; legacy executable and protocol names remain compatible.

All 26 Computer-Link branch trees, 92 commits, wiki history and 123 source files
were preserved and independently checked. Historical Git bundles are retained
in a private checkpoint pending specific public-upload approval; they are not
embedded in the public source archive. Public verification uses the exact
recorded upstream revisions when local bundles are unavailable. Original Python diagnostics and the
separate utility recipes remain available in source. The migration map records
each capability's active route and the original acceptance boundaries.

The desktop Connections screen exposes component availability, native launch
and stop, and a real status-only MCP test. Normal file, terminal, browser,
desktop and saved-task tools remain usable when native components are absent.
Native snapshots retain their local selection and approval workflow.

## Recovery and release integrity

Installation uses verified payload files, versioned releases, atomic receipts
and recovery journals. Repair does not grow duplicate release history. Recovery
and uninstall preserve later installations' registrations and user-modified
files. Native launches require a matching ownership receipt and executable hash.

Release assembly checks production mode, exact source/version identities and
artifact hashes. Hosted Windows acceptance is recorded separately from compiler
and fixture results. Published artifacts are not silently overwritten.

## Acceptance and distribution limits

The build and runtime receipts accompanying this release are the authority for
executed checks. Local Linux process tests and cross-compilation do not prove
Windows GUI behavior. Hosted Windows and browser gates run against the release
source before the automated release job can publish. Physical sound, user-PC
browser coverage and signed-in account round trips still require target-machine
acceptance.

The Windows executables are unsigned. Firefox permanent distribution requires
signing. The build records whether public Google/GitHub OAuth client IDs were
provided; unprovisioned builds do not certify account backup connections.
Permission decisions remain direct user actions. No consent clicks, hidden
browser-profile injection or remote-debugging enrollment are performed.

This version is published as a **prerelease** while those distribution and
target-account acceptance gates remain open.
