# Project Constellation v0.14.10 — State Convergence

v0.14.10 fixes a live-state split-brain regression where a chat could visibly recover to **Tool working** while its tab remained trapped in the Constellation **Needs Attention** group.

## State convergence

- Live Sentinel no longer reads a stale current-version HUD `data-state="tool-stalled"` back as authoritative watchdog truth. Stall/dead/provider-failure state is re-derived from current evidence; only richer Capacity Guard states are imported from the content-owned HUD.
- The current Health Core owns the v8 Execution Pulse renderer. Live Sentinel no longer races it by repainting the same current-version HUD.
- Sentinel emits a small sanitized state-transition event and the content health renderer performs an urgent bounded refresh, keeping visible title/detail/timers aligned with canonical Sentinel state without introducing a second renderer.
- Fresh `tool-running` evidence clears an older content-loop stall instead of pinning the chat in Needs Attention. True current Sentinel stalls and capacity warnings remain primary.

## Self-healing managed tab groups

- Project Constellation commits a tab-presentation signature only after Chrome confirms the requested managed-group reconciliation actually succeeded.
- A transient `chrome.tabs.group` / `chrome.tabGroups.update` failure no longer turns a wrong group into a permanently cached success. Failed reconciliation schedules a bounded retry.
- Each live Pulse census audits Constellation-owned groups against the canonical live bucket and repairs drift automatically. User-created groups are never moved.
- Active and Needs Attention Constellation groups are expanded when used so live work and required intervention are visible instead of silently hiding in a collapsed group.

## Hot-upgrade resilience

- Background state pushes from pre-v0.14.10 Sentinel instances are rejected rather than allowing an old listener to push a newly healthy tab back into warning.
- Direct Sentinel reads also require the current version, forcing the normal hot-injection path when an already-open tab still has an older listener.
- Legacy HUDs still receive hot-upgrade repair; the current v8 HUD remains single-owner.

## Preserved safety and watchdog behavior

- v0.14.9 Interruption Guardian remains intact, including explicit-user-only native Retry and current-turn error ownership.
- v0.14.8 No Surprise Navigation remains intact: passive monitoring does not open, focus, navigate, recreate, or reload ChatGPT.
- v0.14.7 Runway Sentinel behavior remains intact: unchanged real tool work still ages into a stall and long existing conversations still become capacity handoff without requiring a page refresh.

## Regression coverage

- Added an exact screenshot-shaped state-convergence smoke: a legacy warning HUD plus fresh `Inspecting ModForge source and report formats` progress must recover to `tool-running` and repair the legacy HUD.
- Added a managed-group convergence contract that injects a transient group API failure, proves the failed move is not cached, and proves the same healthy state self-heals into Active on retry.
- Stability coverage verifies Completed → Active → Completed convergence while background/network activity churns, without false warning frames.
