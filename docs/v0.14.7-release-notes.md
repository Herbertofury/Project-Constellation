# Project Constellation v0.14.7 — Runway Sentinel

## Why this release exists

Two separate false-confidence paths could hide the exact problems Constellation is supposed to surface:

1. Conversation Capacity Guard mostly counted turns and text observed after the current content script mounted. Reloading/updating the extension inside an already-long chat could therefore make that chat look artificially young.
2. Live Sentinel treated an unchanged active spinner/tool label and repeated `running` transcript polls as fresh progress. A genuinely stuck response could keep resetting its own watchdog clock forever.

v0.14.7 removes both failure modes and makes the result visible everywhere Constellation reports chat state.

## Runway Guard v2

- ChatGPT's MAIN-world transcript probe now reduces the full active conversation branch to numeric metadata: visible turn count, active-branch message count, measured text characters, recent average turn size, current assistant size, and response timestamps.
- Conversation text and authentication data still do not cross into extension state; only bounded numeric/sanitized metadata does.
- Stored IndexedDB history now contributes both turn count and measured character count, so the early-warning calculation survives extension reloads and page remounts.
- Capacity uses the strongest available evidence across stored history, mounted/session observations, and ChatGPT's full active branch instead of trusting the smallest source.
- Heavy recent turns can trigger a predictive warning before the fixed safety threshold when the measured runway is approximately three average messages or less.
- Capacity warning, handoff, and reached states are now canonical **Needs Attention** states in Chat Pulse, not just HUD decoration.

OpenAI's current ChatGPT documentation shows that limits vary by model/mode/plan. Constellation therefore keeps conservative user-configurable safety thresholds and explicit provider-limit detection rather than claiming an exact remaining token ceiling.

## Response Chronograph

Execution Pulse now separates two clocks:

- **Response time** — total elapsed time for the current output, preserved through tool work and finalized when the turn completes.
- **No progress** — time since the last meaningful observable movement.

For ChatGPT, the timer can anchor to the current branch's response creation time even when Constellation attaches mid-response. A regenerated assistant branch uses its own response timestamp rather than incorrectly inheriting the original user-message age.

## Meaningful-progress stall detection

A heartbeat now requires evidence that actually changed:

- assistant output length grew;
- current tool/progress label or structured tool state changed;
- ChatGPT transcript current node/status/progress/tool count/assistant size changed;
- current-turn DOM or provider request lifecycle produced a real new event.

A spinner that remains on screen with the same label is **activity evidence, not progress evidence**. Repeated transcript polls that merely continue to say `running` no longer reset the watchdog. This lets quiet → stalled → dead escalation age correctly while still protecting long tool calls that are demonstrably moving.

## Warning delivery that is hard to miss

- Sentinel now carries authoritative v6 watchdog and capacity states into the canonical live-tab record.
- Hot upgrades now inject the current Health Core together with the Sentinel. Already-open legacy tabs can therefore classify stalls and runway danger immediately without waiting for a page refresh or content-script remount.
- Chat Pulse, native tab status/grouping, toolbar attention counts, and Execution Pulse agree on stall/runway attention.
- Added a separately toggleable **Stall & runway alerts** setting. It emits a one-shot native notification when a chat first enters a proven stall/dead state or crosses a capacity watch/handoff/reached threshold.
- Completion notifications remain independently configurable.

## Performance

- Full stored-capacity aggregation uses a 15-second bounded cache so high-frequency streaming captures cannot force a full IndexedDB cursor scan every few seconds.
- ChatGPT transcript proof remains bounded and metadata-only after MAIN-world reduction.
- Existing Pulse hot-injection, per-tab probe deadlines, local caches, and visibility-aware refresh behavior are preserved.

## Verification target

A releasable v0.14.7 must prove all of the following:

- an unchanged tool label ages the no-progress clock instead of refreshing it;
- a real tool-label change resets the no-progress clock while total response time keeps increasing;
- authoritative watchdog state survives the faster Sentinel repaint and becomes canonical Chat Pulse attention;
- full active-branch counts/chars/timestamps are produced without exposing transcript text or access tokens;
- stored/transcript capacity survives tiny mounted-DOM/session counts;
- predictive heavy-turn runway warning works;
- native completion and capacity/stall notifications fire only on the intended state transition;
- an already-open legacy tab gains v6 stall/runway classification through hot injection with no page refresh;
- existing Output Vault, Pulse Navigator, branch/handoff, OAuth, provider, performance, and persistence regression suites remain green.
