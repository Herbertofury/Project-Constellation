# Project Constellation v0.14.7 — Deep State Engine

## Chat condition engine

- Correlates the newest visible user turn with ChatGPT conversation-tree metadata before trusting terminal state.
- Adds explicit lifecycle conditions for queued/running, waiting-for-user, completed, incomplete, failed, and cancelled states.
- Treats an authoritative current-turn terminal transcript state as sticky for that generation epoch; stale DOM/network evidence cannot resurrect the completed/failed/cancelled turn.
- Resets terminal state, transcript cache, progress, and settling state when a new user turn begins so prior-response state cannot leak into the next generation.
- Reports numeric progress only when ChatGPT exposes a real widget/task percentage; null/absent progress remains unknown rather than becoming a fake 0%.
- Exposes evidence confidence (`authoritative`, `strong`, `medium`, `weak`) and the generation epoch for diagnostics.
- Uses public OpenAI Responses lifecycle semantics as a design reference only. It does not ask for or expose an OpenAI API key and does not pretend a public API response maps to a consumer chatgpt.com conversation.

## Safety and compatibility

The same-origin ChatGPT conversation endpoint is treated as an internal compatibility probe and remains defensive/fallback-capable. DOM and network evidence remain useful when transcript proof is unavailable, but only current-turn evidence can change the current generation state.
