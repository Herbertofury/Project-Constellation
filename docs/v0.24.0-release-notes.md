# Project Constellation v0.24.0 — Durable observations and reliable recovery

This release continues from the verified v0.23.0 commit
`7fe2bf40e1f207b8980c8bd68f2a24b647667f6b`. It preserves the original project,
conversation, desktop and Computer Tools capabilities while repairing failures
across storage, worker restarts, browser lifecycle and local native transport.

## Browser monitoring survives failed writes and interrupted work

A failed browser-storage write no longer leaves an in-memory observation that
can later be acknowledged as if it reached disk. The service retains dirty state
and retries persistence before acknowledging the observation. Startup tab
reconciliation uses the returned run/document identity and observation time
instead of copying an old identity or treating a delayed response as fresh.
Delayed navigation and close events cannot retire a newer document or run.

Sensor sends have a bounded acknowledgement deadline as well as bounded retries.
A document placed in the browser's back/forward cache pauses observation and
resumes with fresh evidence when restored. A hung background response cannot
block the sensor indefinitely. These changes do not send provider requests,
edit drafts or operate consent controls.

After an interrupted alert claim, a notification can recover using its stable
identifier. Audio that had not started remains eligible to retry. Audio already
claimed for playback has an uncertain outcome: the delivery is recorded as
**interrupted** with a visible error, rather than silently succeeding or replaying
possibly delivered sound. **Test alert** remains an explicit check.

## Durable native ordering and complete Windows transport

The Rust hub persists advancing observation watermarks before acknowledging
them. Exact duplicate retries still avoid an extra durable write or broadcast.
A failed write returns a persistence failure and leaves the prior accepted state
intact. An abrupt process stop after a successful acknowledgement cannot erase
the newer ordering evidence. Accepted source-clock skew survives restore within
the same protocol bound; it is not incorrectly clamped to the hub's current time.

Closed observations now pass timestamp and context validation before removing
a session. Browser bridge closes carry the existing document/run metadata so
late closes cannot remove newer problems. Wire protocol version 1 is retained.

Windows Computer Tools reads complete authorization and token frames across
partial byte-pipe reads. The same deadlines, cancellation/revocation controls
and peer checks remain in force. Fragmentation is a supported transport behavior,
not evidence that a request is unauthorized. The original Computer-Link source,
history and integration-delta provenance remain preserved.

## Installer recovery preserves relocated sensor folders

Setup now rejects an active browser folder that is a symbolic link or Windows
junction before starting the install/repair/rollback transaction. Previously,
such a link could be moved into a backup, the transaction could report success,
and cleanup would then reject the linked backup on every later operation.

If an older installation already has that committed journal, recovery preserves
the link entry at a reported `preserved-browsers-link-*` path without traversing
or modifying its target. Live and dangling links are handled; cleanup can
complete and subsequent repair/uninstall remains usable. New transaction tests
verify external bytes, receipts and registrations remain intact, including
actual Windows junction cases in the hosted gate.

## External recovery records what actually happened

The external scheduler supervisor saves a recovery incident before optional
PR or diagnostic work. A repository policy block on Actions-created PRs therefore
does not prevent incident creation. The run reports **blocked** explicitly;
unexpected failures still fail the job and retain their evidence.

The diagnostic workflow dispatch no longer sends the undeclared `target_tasks`
input. Its role is described accurately: it runs isolated CI fixtures and CDP
tests, and its dispatch does not prove live task recovery. Runs using the updated
operational workflow definitions read current default-branch audit evidence,
including manual dispatches and reruns of those definitions. A pre-fix historical
rerun retains its original workflow revision; start a fresh default-branch dispatch
after upgrading to use the repaired supervisor.

Audit validation rejects malformed, timezone-free, invalid-threshold and
excessively future timestamps. The supervisor's 75-minute threshold and the
independent hourly monitor's four-hour threshold remain separate. A stale
committed audit means fresh evidence is missing; it does not establish current
ChatGPT service health. No heartbeat is fabricated by this release.

Repeated unchanged incidents reuse their existing issue without comment spam.
Diagnostic dispatch and PR work persist an attempt claim before their side
effects, with a one-hour cooldown after failed or uncertain attempts. Invalid
or future persisted claim timestamps cannot suppress diagnostics forever.
Only the latest default-branch watchdog failure/timeout may retry, up to three
total attempts; a newer success, running job, cancellation or approval requirement
prevents retrying an obsolete failure.

Read [the watchdog guide](TASK-WATCHDOG.md) for actual workflow roles, evidence
files and permission-block diagnosis. Repository permissions and user consent
decisions remain explicit; the supervisor does not replace credentials or alter
administrative policy.

## Configured GitHub sign-in is no longer rejected by its own build guard

The production build previously replaced the GitHub client-ID placeholder in
both its declared constant and the runtime check used to reject placeholders.
That made the check reject the actual configured ID. This was reproduced from
the immutable v0.23.0 Extension ZIP even though its receipt correctly recorded
that a product client ID was present.

The build now replaces only the declared configuration constant. Regression
checks execute the generated accessor, retain rejection of unprovisioned builds
and validate Google manifest provisioning separately. Release inspection checks
the shipped extension itself as well as its receipts. Existing product IDs and
the stable extension identity are retained; ordinary configured-release users
sign in through Accounts & Connections without creating new OAuth applications.
Authenticated backup, restore and revocation still require account acceptance.

## Verification and release contract

The source checkpoint records local candidate evidence in
[MONITOR-VERIFICATION.md](MONITOR-VERIFICATION.md). Matching completed hosted
workflows and attached release receipts establish the final source commit/tree,
actual Windows and installed-browser execution, and published artifact hashes.
Prepared tests or cross-compilation alone are not Windows acceptance.

The release retains all existing root, desktop, native, installer, browser and
Computer Tools gates. New regressions cover failed durable writes, abrupt
restart ordering, delayed closes, sensor/background interruption, fragmented
Windows frames, invalid audit evidence and independent recovery failures. Every
published installer/ZIP is bound to the accepted source and verified bytes.

The selected stable stack remains Electron 45.5.0, electron-builder 26.18.1,
Node 26.13.1, Rust 1.100.1 and Playwright 1.65.2. The changed operational
workflows pin github-script v9.0.0 to its verified commit. See
[RELEASE-STACK-0.24.0.json](RELEASE-STACK-0.24.0.json). Mandatory pinned
shrink-anything, fast-anything and rust-anything assessments, plus the scoped
Google migrate-to-rust applicability decision, are recorded in
[RELEASE-OPTIMIZATION-0.24.0.json](RELEASE-OPTIMIZATION-0.24.0.json).

No content, test coverage or matching dashboard rows are removed to create a
performance claim. The v0.23.0 renderer improvement is retained; its historical
benchmark is not presented as a new v0.24.0 measurement. Persisting newly required
native ordering evidence has a real I/O cost and is assessed as a correctness
requirement, not advertised as a speedup over an unsafe acknowledgement.
Five alternating Linux runs of the final-version native binary retained all
96 sessions and 192 incidents. The median of per-run advancing-acknowledgement
medians rose from 0.159 ms to 1.297 ms while every accepted watermark became
durable. Exact-retry medians were 0.150/0.155 ms, with zero duplicate broadcasts
or retry writes. Full results, tail variation, source hashes and environment
limits are in [NATIVE-ACK-PERFORMANCE-0.24.0.json](NATIVE-ACK-PERFORMANCE-0.24.0.json).

## Downloads and upgrade

Start with **Constellation-0.24.0-Windows-Setup.exe**. It installs the native hub,
stages browser sensors and includes Computer Tools. Full desktop installer and
portable ZIP, Chromium extension, Firefox sensor, Linux hub, exact source ZIP,
runtime receipts and SHA-256 checksums ship in the same release.

Preserve working account configuration and local data. Follow
[Windows Setup](WINDOWS-SETUP.md) or [Installation](INSTALLATION.md), verify the
matching checksum, then reload each enabled browser sensor. Every monitored
browser/profile needs its own sensor. Use Repair and the retained rollback
controls when needed; do not remove an existing extension just to change its
unpacked directory, because removal can erase its browser storage.

This remains a **prerelease** while Windows publisher signing, permanent Firefox
signing, physical audio/system-notification confirmation, owner profile enrollment
and authenticated account round trips remain open. Production OAuth provisioning
is recorded in the actual build receipts; it does not prove account acceptance.
Historical releases and private Computer-Link history bundles remain intact.
