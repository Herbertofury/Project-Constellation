# Project Constellation v0.14.2 - Live Sentinel Hotfix

v0.14.2 fixes the false **Chat complete** state that could appear while ChatGPT was visibly still searching, inspecting files, calling tools, or otherwise working.

## Root cause

v0.14.1 combined current tool labels with final-answer controls such as **Copy**. ChatGPT can leave those controls mounted on the previous assistant answer while the new turn's agent/tool progress is rendered elsewhere in the page. In that DOM shape, an old Copy button could incorrectly veto newer live work. The old tool scanner could also choose a historical completed row such as `Searched 20 websites` instead of a newer `Searching the web` or `Inspecting ...` row.

## What changed

- **Live Sentinel:** a small dedicated live-state detector now owns running/completed classification. It examines the current conversation frontier rather than the whole historical page.
- **Current work outranks old controls:** present-tense progress after the newest user turn keeps the chat Active even when an older assistant answer still has Copy/feedback controls mounted.
- **Much broader tool vocabulary:** search, inspect, check, analyze, review, compare, audit, build, compile, package, verify, test, edit, write, patch, modify, implement, fix, enhance, persist, port, open, click, type, trigger, upload/download, and related progress verbs are recognized.
- **Newest current progress wins:** Execution Pulse now reports the newest active row in the current response instead of a stale completed row from chat history.
- **In-place text transitions:** character-data changes such as `Searching...` becoming `Searched...` are observed immediately.
- **Hot upgrade for open tabs:** Project Constellation injects the Sentinel into already-open supported AI tabs after installation/update and when Chat Pulse queries a tab that lacks it. You do not have to manually reload every ChatGPT tab to replace the old detector.
- **Legacy HUD repair:** the injected Sentinel can update an already-mounted Execution Pulse HUD, correcting a stale `Chat complete` label in place.
- **Single source of truth:** popup Chat Pulse, completion notifications, main content health, and the on-page HUD consume the same canonical Sentinel state whenever available.

## Regression reproduced

The v0.14.2 Chromium smoke fixture mirrors the reported failure: an older completed assistant turn still exposes Copy controls, a newer user turn is followed by current progress outside a recognized assistant message, and the page contains `Searched 20 websites`, `Searching the web`, `Inspecting mob animation rendering logic`, and generic `Called tool` rows. The test requires Project Constellation to report `running`, choose `Inspecting mob animation rendering logic` as the current activity, and overwrite a legacy HUD that initially says `Chat complete`.

The fixture then mutates the live progress rows in place to completed tense and mounts the new assistant's final answer. Only at that point may the state become `idle`/completed.

## Test focus

Load v0.14.2 over v0.14.1 with several ChatGPT tabs already open. Do **not** refresh those ChatGPT tabs first. Open Project Constellation once so the hot Sentinel census runs. A tab showing live `Searching...`, `Inspecting...`, tool calls, or comparable current work should show **Active / Tool working** rather than **Chat complete**. When the current response actually settles, it should transition to Completed and, if enabled, emit the completion notification.
