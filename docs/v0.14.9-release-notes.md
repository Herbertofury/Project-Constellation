# Project Constellation v0.14.9 — Interruption Guardian

v0.14.9 turns provider message failures into first-class, actionable chat states without weakening v0.14.8's **No Surprise Navigation** safety contract.

## New interruption states

- **Message delivery timed out** (`delivery-timeout`)
- **Connection interrupted** (`connection-interrupted`)
- **Response interrupted** (`response-interrupted`)
- **Message was not sent** (`send-failed`)

The exact ChatGPT surface `Message delivery timed out. Please try again.` is no longer collapsed into the misleading generic `refresh-required` state.

## Safe recovery

When the current provider failure surface exposes an exact native **Retry**, **Try again**, **Regenerate response**, **Resend message**, or **Reconnect** control, Execution Pulse reports it and exposes a matching recovery button. That action is always explicit and user-driven. Project Constellation never retries automatically, because the interrupted turn may already have performed tool/app side effects.

If no safe native recovery control is visible, Constellation reports the interruption and leaves refresh/manual recovery as the fallback. It does not guess that the prompt was delivered, and it does not silently reload the page.

## Better evidence and reporting

Interruption state carries the provider failure kind, detection age, native recovery availability/label, preserved partial assistant character count when measurable, and whether tool activity preceded the failure. Chat Pulse, Needs Attention, integrity findings, tab presentation, and one-shot native attention notifications use the same specific failure state.

Runway Sentinel still owns response time, no-progress aging, stall/dead detection, and conversation runway. An explicit provider error outranks stale `running` transcript/DOM evidence so a timed-out response cannot remain falsely green.

## Safety invariant

Passive monitoring may observe, classify, notify, badge, and record. It may not open, focus, recreate, navigate, reload, or retry ChatGPT. A provider recovery control may only be activated by an explicit user recovery action in an already-open tab.
