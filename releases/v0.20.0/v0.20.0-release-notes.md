# Project Constellation 0.20.0 — Reliability Foundation

Project Constellation 0.20.0 turns the unified 0.19 product into a more event-driven, self-diagnosing, self-recovering desktop + browser platform while preserving the broad provider/permission model and the stable Constellation browser-extension identity.

## Highlights

- **Event-driven state bus.** Home, side panel, Pulse, desktop status, provider health, catalog/capture state, and recovery surfaces can react to meaningful state transitions instead of relying on fixed refresh loops.
- **Polling reduction without capability loss.** Side-panel refresh, Local Work route tracking, Pulse collapsed-state refresh, Home recovery/status refresh, desktop ChatGPT route tracking, and the stall watchdog now use events with bounded one-shot fallbacks where a safety net is useful. The stall watchdog schedules only the next chat deadline that could actually become stale instead of waking every minute while idle.
- **Provider capability health.** Provider surfaces now report explicit capabilities such as provider detection, route detection, composer/send controls, message surfaces, chat/project context, and streaming observations. Constellation scores the adapter, records degraded/broken states, and exposes them in System Health.
- **Incident Brain.** Recovered failures can be fingerprinted, counted, resolved only with verification evidence, and retained as reusable recovery recipes with invalidation conditions and regression protection. Provider adapter recovery is integrated into this system.
- **Brain DB v11.** Provider health, incident recipes, and migration receipts are first-class durable stores. IndexedDB access now goes through a shared connection manager with safe version-change handling rather than opening/closing a connection around every operation.
- **Modular background routing.** New background services use a handler registry instead of extending the legacy service-worker switch indefinitely. Existing message behavior remains compatible while the architecture can be migrated incrementally.
- **Integrated Update Center.** The desktop can check the stable GitHub release channel, verify SHA-256 before staging an update, install after the app exits, retain a previous install as rollback state, and restore it on failed replacement. It performs a single startup availability check rather than permanent update polling.
- **Project Constellation desktop identity.** User-facing Commander branding is consolidated under Project Constellation while the existing application ID, state directories, CLI aliases, extension ID, and migration-sensitive bridge contracts stay compatible.
- **Electron 44.4.4.** 0.20.0 moves from 44.4.3 to the current stable 44.4.4 line while retaining electron-builder 26.16.1.
- **Windows process reliability.** PowerShell-backed local commands execute from a short-lived UTF-8-BOM `.ps1` wrapper with fail-fast exit propagation. Explicit simple native calls such as `& 'program.exe' ...` now bypass PowerShell native-command re-serialization and launch with structured argv, preserving embedded quotes and large/partial output byte-for-byte; real PowerShell pipelines, functions, expansion, and explicit shell overrides stay on the normal shell path. PowerShell 7 remains preferred, with Windows PowerShell 5.1 as a compatibility fallback.
- **Packaged ChatGPT hook integrity.** The desktop carries an explicit packaged mirror of the canonical browser page hook, with a byte-for-byte regression check so source and packaged injection logic cannot silently drift.
- **Deterministic Electron acceptance.** The integrated Electron runtime proof now waits for the shell-runtime health result to settle before accepting the first successful tool-result delivery, eliminating a Windows timing race without delaying normal user execution.
- **Fail-fast modern CI.** Windows PowerShell jobs now promote native command failures to CI failures, and workflows use the current Node-24 GitHub Actions line rather than deprecated Node-20 action runtimes.

## Windows release proof

0.20.0 adds a dedicated Windows runtime gate designed to execute the exact release source on `windows-latest`, including:

- the complete desktop regression/security suite;
- native Windows display, cursor, keyboard, window, clipboard, screenshot, UI Automation, and MCP image-return checks;
- the real integrated Electron ChatGPT/local-agent smoke;
- a fresh Windows installer + portable ZIP build;
- extraction and launch of the produced portable application;
- SHA-256/size receipt generation for the Windows deliverables.

The unified release workflow requires Linux/browser verification and Windows-native verification before publication.

## Release pipeline

The 0.20 release toolchain generates the extension ZIP, committed-source ZIP, Windows portable ZIP, optional Windows installer, release notes, SHA-256 manifest, and machine-readable release receipt from one source revision. The source archiver writes raw Git blob bytes rather than export-converted working-tree text, so CRLF-attributed PowerShell files remain byte-identical to the committed tree. Published release bytes are treated as immutable; a later fix receives a new version rather than silently replacing an old release.

## Permission model

0.20.0 intentionally **does not reduce Project Constellation's browser permission or provider host coverage**. Broad browser/provider integration remains a product direction. New permission-regression tests guard against accidental capability loss.

## Recovery and safety

- Existing permission/security/login/user-draft/ambiguous-UI holds remain non-bypassable.
- The stable browser extension ID remains `geljambmkfjkhodgkpjhnmfojkpcamig`.
- Existing Commander-era app state/CLI paths are retained where changing them could break upgrades or user data.
- Update installation verifies downloaded bytes before replacement and keeps a rollback copy of the previous app directory.
- Incident recipes require verification evidence before they can be promoted as resolved recovery knowledge.

## Compatibility

User-configured Google Drive and GitHub connections remain supported. Distribution builds do not embed private OAuth client secrets. A production package may be created without embedded client IDs for environments where the user supplies/configures connections separately; the build receipt records whether OAuth IDs were actually embedded.

- Made Linux desktop Chromium acceptance use the Playwright-managed browser installed by CI and made unified extension ZIP packaging sorted/file-only so verified extension bytes reproduce deterministically.
